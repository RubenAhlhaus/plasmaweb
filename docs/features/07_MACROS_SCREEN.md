# Macros & program queue

## Purpose

The **Macros** screen (`src/screens/MacrosScreen.tsx`) combines preconfigured machining steps (tiles on the left) with a **program queue** on the right. On wide viewports these are **side by side**; below ~1024px width the queue moves **below** the tile catalog (fluid width up to ~35% / 28rem when side by side). The queue lives in the **app store** (`macroQueueItems` / `setMacroQueueItems` in the UI slice, see `src/store/uiSlice.ts`) and persists when switching to other screens and back (session-local, no `localStorage`). **Program header** (coordinate system, units, optional machine-Z safety retract; generated G-code also fixes **G90** and **G17**) is stored separately as **`macroQueueProgramSetup`** / **`setMacroQueueProgramSetup`** (type [`macroQueueSetup.ts`](../../src/types/macroQueueSetup.ts)); it is **not** part of `macroQueueItems`, is reset with **`resetProgramEditor`**, and in [`generateMacroQueueProgram`](../../src/lib/macroGcode/emitProgram.ts) is inserted as the first G-code line(s) after comments (`formatMacroQueueSetupGcode` / `formatMacroQueueSetupGcodeLines`). **“Go to program”** translates the queue with this setup into a **G main program**, saves it on the control PC under `PROGRAM_PREFIX`, opens it in LinuxCNC, and fills the **Program** editor (see below). **Nested blocks** (`kind: 'pattern'`) expand to execution order **phase × position** (each phase in sequence at all pattern points — tool-friendly), consistent with [`macroQueueDrag.ts`](../../src/lib/macroQueueDrag.ts).

## Data model

Types in [`src/types/macros.ts`](../../src/types/macros.ts):

| Type | `kind` | Meaning |
|-----|--------|-----------|
| `MacroQueueItem` | `'macro'` | One concrete step (e.g. drilling) with `macroTypeId` and `params`. |
| `PatternQueueItem` | `'pattern'` | **Nested block**: container with `children: MacroQueueItem[]` (phases). |
| `QueueItem` | — | Union of both. |

Additionally (not in `QueueItem`):

| Type | Storage | Meaning |
|-----|---------|---------|
| `MacroQueueProgramSetup` | `macroQueueProgramSetup` in `UISlice` ([`macroQueueSetup.ts`](../../src/types/macroQueueSetup.ts)) | Fixed program header: WCS (`G54`–`G59`), units (`G20`/`G21`), and **`retractZToMachineZero`** (default **`true`**): when enabled, emit **`G53 G0 Z0`** after the preamble **and** again before each mid-queue tool change (different T number; see [Mid-queue tool change clearance](#mid-queue-tool-change-clearance)). Emission with `G90 G17` via [`formatMacroQueueSetupGcodeLines`](../../src/types/macroQueueSetup.ts). |
| `MacroParamSection` | type in [`macros.ts`](../../src/types/macros.ts) | Section in the parameter dialog: `heading` (subheading) and `keys` (parameter keys in display order). |
| `MacroDefinition.paramSections` | optional per entry in [`macroDefinitions.ts`](../../src/data/macroDefinitions.ts) | Groups fields under headings and defines **display order**; **keys** match entries in `params`. In [`emitProgram.ts`](../../src/lib/macroGcode/emitProgram.ts) and subroutines only the **subset defined for that macro** is used — **`einstechtiefeMm`** for **standard drill** becomes peck depth in the `o<lcncgui_drill>` call (**#8**). **#10** (chip-break retract) is currently fixed by the generator to **`DRILL_CHIP_BREAK_RETRACT_MM`** (1 mm) when peck is used and **full retract** is off; no separate numeric dialog field. **`fullRetract`** (options toggle) becomes call **#11**: when pecking and on, each intermediate peck retracts to the feed-start height (**surface Z + approach / `vorschubHoeheMm`**, Bohrungsstart) instead of the short chip-break lift. Ignored when not pecking (dialog toggle is disabled in that case). Details: `lcncgui_drill.ngc` and [`resources/linuxcnc-subroutines/README.md`](../../resources/linuxcnc-subroutines/README.md). Other dialog-only keys may exist without being used by the emitter. If `paramSections` is missing, the generic form stays ungrouped. Parameters not listed in any section appear at the end of the generic dialog in **visible state key order** (like `Object.entries` on dialog params), without an extra heading.

The current root queue list is **`macroQueueItems`** in state (`UISlice` in [`src/store/types.ts`](../../src/store/types.ts)); `MacrosScreen` reads and updates it only through the store.

The **drill pattern** tile (nested position block) is in [`src/data/macroDefinitions.ts`](../../src/data/macroDefinitions.ts) (`NESTED_QUEUE_BLOCK_MACRO_ID` value `nested-pattern-block`). The parameter dialog is a **dedicated form** (tabs: custom / round / rectangular layout) with validation in [`patternMacroDialogValidation.ts`](../../src/components/macros/patternMacroDialogValidation.ts); there is **no** `paramSections` for this macro. Stored fields include `patternType` (`custom` \| `round` \| `rectangular`), for custom layout `customPatternPoints` as JSON array of `{ id, x, y }` (stable `id` for UI; G-code uses only `x`/`y`). Older queue entries with `cartesian` / `polar` are mapped to `rectangular` / `round` when the dialog opens. Pattern expansion: [`expandPatternPositions`](../../src/lib/macroGcode/expandPatternPositions.ts) (invalid `customPatternPositions` errors there instead of silent fallback coordinates). For **round** / polar layouts, **start angle 0°** places the first hole **directly above the centre (+Y)**; angles increase **counter-clockwise** (90° = −X). **Display name** of a block comes from `params.name` (optional); without it the UI uses the fallback **“Pattern block”** — centrally via [`patternQueueDisplayLabel`](../../src/lib/macroQueueLabel.ts) in `src/lib/macroQueueLabel.ts`.

## UI & flow

- **Program header** (top of right column before the sortable list): fixed card **without** drag & drop; click opens its own dialog ([`ProgramQueueSetupBlock`](../../src/components/macros/ProgramQueueSetupBlock.tsx)) for WCS, units, and the **machine-Z retract** toggle (`retractZToMachineZero`, default on). Controls both the preamble retract and mid-queue clearance before tool changes (see [Mid-queue tool change clearance](#mid-queue-tool-change-clearance)). Default emission: `G21 G90 G17 G54` then `G53 G0 Z0`. Visible even with an empty queue.
- **Tiles on the left:** Open the parameter dialog (`MacroParamDialog`). Normal macros are inserted into the **root queue** or the last selected **nested block** depending on target. **Insert target** (“Macro here” on block vs. end of program) is **local React state** in `MacrosScreen`: it is lost when switching to another sidebar screen (back to root target), while the **queue itself** stays in the store.
- **Machine macros (user `.ngc`):** Extra tiles under category **Machine** come from INI **`[MACROS] MACRO=…`** entries (gmoccapy-style; first token = O-word name; optional arg placeholders ignored for now). Each name must resolve to a `.ngc` under `[RS274NGC] SUBROUTINE_PATH`. Built-in `lcncgui_*` names are skipped. Discovery runs with `machine.get_ini_config` / `machine.ini_config.loaded` → `user_macros` in [`IniRuntimeConfig`](../../src/store/types.ts) (see [`user_macros_ini.py`](../../backend/user_macros_ini.py)); opening the Macros screen re-requests `get_ini_config` so new files/INI edits appear. Each tile/queue id is **`user-ngc-<o-name>`** (file stem = O-word). **Clicking a tile always appends to the root queue** (never as a pattern phase; DnD into a nested block is rejected). No parameter dialog yet — generation emits `o<name> call` with no arguments ([`emitProgram.ts`](../../src/lib/macroGcode/emitProgram.ts)). **Edit:** short info dialog (delete only), not `MacroParamDialog`. Helpers: [`userSubroutineMacros.ts`](../../src/data/userSubroutineMacros.ts).
- **Go to program** (English label; formerly “Zum Programm”): once there is at least one queue entry, the green button appears at the bottom (`data-e2e="macros-generate-program-code"`). While generating it is **disabled** and shows **“Generating program…”**.
  - **Event-bus trigger:** the button publishes `ui.macros.generateProgram` (`source: 'macrosScreen'`) and does not call backend logic directly.
  - **Flow** (hook [`useMacroQueueProgramGeneration`](../../src/hooks/useMacroQueueProgramGeneration.ts)): subscribes to `ui.macros.generateProgram`, builds G-code via `generateMacroQueueProgram(queue, tools, macroQueueProgramSetup)` in [`src/lib/macroGcode/emitProgram.ts`](../../src/lib/macroGcode/emitProgram.ts), then runs the backend chain.
  - **Backend chain:** `program.list` (default directory under `PROGRAM_PREFIX`) → `program.write` (`lcncgui_queue_<timestamp>.ngc`) → `setProgramEditor` (content + path) → `program.open` → `program.read` (sync editor with file from control PC) → sidebar **Program**.
  - **Errors:** toasts on validation failure, `program.list`/`program.write`/`program.open`/`program.read`; a second start while a pipeline runs is rejected.
  - **Subroutines:** [`macroSubroutineMap.ts`](../../src/data/macroSubroutineMap.ts); reference `.ngc` and `SUBROUTINE_PATH` under [`resources/linuxcnc-subroutines/`](../../resources/linuxcnc-subroutines/README.md).
- **Edit & delete:** Opening a **built-in** queue entry (root or phase inside a nested block) shows `MacroParamDialog` with a **Delete** button; after confirmation the entry is removed (for a **block**, all phases inside go too). Opening a **machine macro** (`user-ngc-…`) shows a short info dialog (no parameters) with delete; confirmation uses the same delete confirm dialog as built-ins (`overlayClassName="z-[60]"`).
- **Target “phase in block”:** **“Macro here”** on the nested block (`PatternQueueBlock`) means the **next** tile-added macro is **appended to that** block. The hint “Next macro …” can be reset to **“To program end instead”** (root target).
- **Nested phase XY (standard drill / helical bore):** When adding or editing a phase **inside** a drill pattern, hole **X**/**Y** are **not** editable in `MacroParamDialog` (`xyProvidedByPattern`). Positions come only from the parent pattern; G-code expansion (`expandPatternBlock` / `mergeXYIntoParams`) overwrites child `x`/`y` with each pattern point. The dialog hides those fields, skips requiring them on submit (existing stored X/Y are preserved if present), does not pre-fill machine XY for new nested phases, and shows [`MacroFromPatternHint`](../../src/components/macros/MacroFromPatternHint.tsx) (same banner also covers hidden **`surfaceZ`**; see component table). Root (non-nested) drill/helix dialogs keep normal X/Y entry. **Face milling** nested in a pattern is unchanged: `areaStartX` / `areaStartY` stay editable; pattern merge still writes unused `x`/`y` on the child params only.
- **Nested phase Z heights (standard drill / helical bore):** When **adding** a phase inside a drill pattern, `MacrosScreen` passes [`patternHeightDefaultsFromParams`](../../src/lib/macroGcode/patternHeightDefaults.ts) into `MacroParamDialog` (`patternHeightDefaults`) **only in add mode** (not while editing). New nested **standard drill** and **helical bore** phases prefill both **`surfaceZ`** (stored; field hidden in the nested dialog) and **`safeZ`** (editable XY-travel / retract height) from the parent pattern (legacy pattern `safeZ` if still present, otherwise [`defaultSafeZAboveSurface`](../../src/lib/macroGcode/patternHeightDefaults.ts) = **pattern `surfaceZ` + 5 mm**) instead of the machine Z. Edit mode keeps stored heights. Nested forms hide **`surfaceZ`** via [`omitPatternProvidedFields`](../../src/components/macros/macroParamFieldUtils.ts) (same helper also hides X/Y). G-code expansion injects pattern **`surfaceZ`** via `PATTERN_SURFACE_Z_KEY`. **`PATTERN_SAFE_Z_KEY`** is only set when the pattern still has an explicit legacy `safeZ` ([`readOptionalPatternSafeZ`](../../src/lib/macroGcode/patternHeightDefaults.ts)) — otherwise the child’s `safeZ` is used by the emitter (legacy child `startZ` still accepted via [`numSafeZParam`](../../src/lib/macroParams.ts); missing height falls back to the same `defaultSafeZAboveSurface`). Dialog open migrates legacy child `startZ` → `safeZ` ([`migrateLegacyStartZToSafeZ`](../../src/lib/macroParams.ts)).
- **Drag & drop:** Root entries and phases are sortable (`@dnd-kit`). Move/insert logic: [`src/lib/macroQueueDrag.ts`](../../src/lib/macroQueueDrag.ts), collision detection: [`src/lib/macroQueueCollision.ts`](../../src/lib/macroQueueCollision.ts).
- **Drop on the phase area** (inner region under the block header): a macro is **always appended** to the end of the phase list — **not** at the pointer position. **Phase order** is then (or still) set **by dragging handles** inside the block.
- **Tail drop zone** under the list: drop **to end of root queue** (e.g. for macros dragged out of a nested block). Implementation: [`ProgramQueueRootTailDrop`](../../src/components/macros/ProgramQueueRootTailDrop.tsx) with fixed drop id `ROOT_QUEUE_TAIL_DROP_ID` in `macroQueueDrag.ts`.
- **Drag overlay:** [`ProgramQueueDragPreview`](../../src/components/macros/ProgramQueueDragPreview.tsx), cursor-centered via [`programQueueDragOverlayModifiers.ts`](../../src/lib/programQueueDragOverlayModifiers.ts).

## Hint graphics in the macro dialog

- **Scalability:** [`macroHintDefinitions.ts`](../../src/data/macroHintDefinitions.ts) per macro defines **which** hint SVG (`svgPath`), Aria text, and sidebar width apply. The `data-active` value is the **same string as the field’s `params` key**; field→highlight mapping lives in each SVG (`svg[data-active='…']`) and in [`MacroNumericParamField`](../../src/components/macros/MacroNumericParamField.tsx) (via `MacroFieldHintWrap` and `createNumericDialogOpenHandler` from [`useMacroHintDialogHandlers`](../../src/components/macros/useMacroHintDialogHandlers.ts)). Further macros: registry entry plus SVG under `public/macro/` with matching selectors.
- **Examples:** **Standard drill** → `bohrmakro.svg`: `vorschubHoeheMm` (A), `depth` (B), `einstechtiefeMm` (C, peck depth). **Face milling** → `planen.svg`: `areaWidth` / `areaHeight` (labels A/B in graphic), `areaStartX` / `areaStartY`, `cutterOverhangMm` (cutter overhang, dashed outer contour). **Helical bore** → `bohrfraesen.svg`: `x`/`y` (center), `nominalDiameter`, `depth` (not `helixAngle`).
- **SVG:** The graphic controls colors and highlight via embedded `<style>` and `svg[data-active='…']`; prefer editing the file under `public/macro/`.
- **Drill pattern:** No static `public/macro/` SVG; preview is computed from dialog parameters (see [`PatternPreviewSvg`](../../src/components/macros/PatternPreviewSvg.tsx)). Marker coordinates use the same numeric interpretation as pattern expansion ([`patternNumericParam`](../../src/lib/macroGcode/expandPatternPositions.ts) in `expandPatternPositions.ts`). The preview optionally accepts `roundCenterMm` / `centerMarkerEmphasized` (bolt circle center) and `rectGridOriginMm` / `rectOriginMarkerEmphasized` (grid start); coupling to fields via `onDialogOpenChange` and `onTriggerFocusChange` on [`TouchNumericPickerField`](../../src/components/numeric/TouchNumericPickerField.tsx). **`TouchNumericPickerField`** optionally supports `dialogAside` (side panel) and `onDialogDraftChange` (draft while dialog open or `null` on close) for live previews.

## G-code: tool change and length compensation

Each `T… M6` from [`emitToolChange`](../../src/lib/macroGcode/emitToolChange.ts) is followed immediately by **`G43`** (tool length compensation from the tool table). LinuxCNC does **not** apply length offset on `M6` alone. Same-tool repeats still emit `T… M6` / `G43` (mid-queue machine-Z retract between identical tools is separate — see below). The Tools UI uses the same word order in one MDI block (`T<n> M6 G43`) because `program.mdi` accepts a single line — see [`05_TOOL_TABLE.md`](05_TOOL_TABLE.md).

## G-code: face milling

The queue translates **face milling** into a main program: [`emitPlanFaceInvocation`](../../src/lib/macroGcode/emitPlanFace.ts) writes `o<lcncgui_plan_face> call […]` including **`cutterOverhangMm`**, **`vorschubHoeheMm`** (clearance height above stock top), **`surfaceZ`** (current stock top), **`targetZ`** (absolute finished face height; must be below `surfaceZ`), and all other numeric parameters in a fixed documented order. Argument **#8** is **`targetZ`** (absolute cut Z). Argument **#12** is always `0` for now (reserved for a later **path pattern** in the dialog). The reference subroutine **`lcncgui_plan_face.ngc`** is shipped in [`resources/linuxcnc-subroutines/`](../../resources/linuxcnc-subroutines/README.md); argument **#14** carries the tool diameter when available from the selected tool and falls back to `0` otherwise (subroutine-level fallback logic applies).

**UI heights:** The face-milling dialog collects **`surfaceZ`** and **`targetZ`** (not a relative Z step-down). Legacy queue entries that still store **`stepDown`** are migrated on dialog open and when emitting (`targetZ = surfaceZ − stepDown`).

**Deploy note:** Argument **#8** is now absolute **`targetZ`** (previously relative step-down). After updating lcncgui, ensure `SUBROUTINE_PATH` serves the updated `lcncgui_plan_face.ngc` (reinstall or copy from `resources/linuxcnc-subroutines/`), and **regenerate** any previously written face-milling main programs so their `o<lcncgui_plan_face> call` arguments match.

## Subroutine initial approach (raise if needed → XY → Z)

Reference subroutines under [`resources/linuxcnc-subroutines/`](../../resources/linuxcnc-subroutines/README.md) (`lcncgui_drill.ngc`, `lcncgui_helix_bore.ngc`, `lcncgui_plan_face.ngc`) on entry: raise Z to safe/clearance **only if** current Z is below that height, then rapid to the first **XY**, then rapid Z to safe/clearance. That prevents both plunging to safe Z at the previous XY and sweeping XY while the tool is still low. Keep the program-header machine-Z retract enabled when possible so the first XY move starts high. Details: [`resources/linuxcnc-subroutines/README.md`](../../resources/linuxcnc-subroutines/README.md). After updating, redeploy all three `.ngc` files on the controller (`SUBROUTINE_PATH`); the generated main program does not embed this motion.

## Edge cases

### Machine-Z retract (`retractZToMachineZero`)

- Emits **`G53 G0 Z0`** immediately after the preamble and **before** any tool change or macro call.
- When enabled, also drives mid-queue tool-change clearance (see below).
- **Safe only** when machine coordinates have been established (axes **homed**), soft limits allow the move, and **machine Z0 is the safe top** (typical mill after homing with home at max Z). If `HOME_OFFSET` / axis polarity put Z0 elsewhere, disable the option or fix the INI — otherwise the rapid can move toward the workpiece.
- Soft limits may clamp the move short of a mechanical stop; that is still preferable to an unbounded rapid, but does not replace a correct home/Z0 convention.
- When **disabled**, subroutines still raise to their own safe/clearance Z before the first XY if current Z is below that height. That covers a low tool at subroutine entry, but does **not** replace a correct machine-Z0 convention for mid-queue tool changes (see below). Prefer leaving retract enabled when machine Z0 is a safe top.

### Mid-queue tool change clearance

- When **`retractZToMachineZero`** is enabled and consecutive macro invocations use **different** tool numbers, the generator emits **`G53 G0 Z0`** immediately **before** the next `T… M6` / `G43` ([`emitToolChange`](../../src/lib/macroGcode/emitToolChange.ts)), so the spindle clears the workpiece for a manual or ATC tool change.
- Applies from the **second distinct tool** onward; the first `T… M6` / `G43` relies on the preamble retract (same flag), not a duplicate mid-queue line.
- Same-tool repeats (e.g. two drills with the same `toolId`, or pattern expansion of one phase) do **not** insert this retract between identical `T… M6` / `G43` pairs.
- When **`retractZToMachineZero` is false**, neither the preamble nor mid-queue tool switches emit `G53 G0 Z0` (shared escape hatch if machine Z0 is not a safe top).
- Same preconditions as the preamble retract: axes **homed**, soft limits allow the move, and **machine Z0 is the safe top**. Soft limits may clamp the move short of a mechanical stop.
